## Chapter II

### Разворачивание дампа

> Для начала тебе нужно развернуть дамп, который хранится в файле *materials/covid_dump_pg16.tar* в базе данных на виртуальной машине. Для этого:
> 1. Тебе необходимо закинуть этот файл на ВМ с помощью команды **scp** в домашнюю папку пользователя **student**.
> 2. Войти под **root** пользователем с помощью команды `sudo -i`.
> 3. Под рутом скопировать файл с дампом в домашнюю папку пользователя **postgres**, а именно в */var/lib/postgresql/*.
> 4. Под рутом назначить владельцем файла  */var/lib/postgresql/covid_dump_pg16.tar* пользователя **postgres**.
> 5. Войти под пользователем *postgres* (см. [инструкцию](https://applicant.21-school.ru/guide_vm_med)) и перейти в папку с дампом
>  */var/lib/postgresql/*.
> 6. С помощью утилиты **pg_restore** выполнить восстановление от имени пользователя **postgres** в базе **postgres**.
> 
> Теперь ты наконец можешь подключиться к БД с данными. Используй для этого программу **DBeaver**. Настрой в ней подключение
> к базе **PostgreSQL** со следующими кредами:
> - *host* - localhost;
> - *port* - 15432;
> - *database* - postgres;
> - *username* - postgres;
> - *password* - postgres.
> 
> Если ты все сделал правильно, то ты сможешь подключиться к базе. Изучи какие схемы и таблицы в ней находятся. Посмотри комментарии
> к полям в таблицах.
> 
> Если же подключиться не получилось, ты всегда можешь попробовать удалить виртуалку, поднять заново новую и попробовать с нуля
> развернуть дамп.

### Задание 9. Представления

> Так, теперь у тебя есть три отдельных скрипта для трех групп. Хм, правда каждый раз копировать эти скрипты, чтобы обратиться

> 
> В **SQL** есть такой понятие, как представление или **вьюха** (**VIEW**). **Вьюха** - это виртуальная таблица. Она не сохраняет данные
> из твоего скрипта в БД физически, а просто под собой сохраняет сам скрипт и каждый раз выполняет его при обращении
> к ней. Подробнее сам прочитай, что это.
> 
> А теперь я хочу, чтобы ты создал три вьюхи:
> 1. *covid.daily_statistics_country_level* - для 1 группы.
> 2. *covid.daily_statistics_region_level* - для 2 группы.
> 3. *covid.daily_statistics_mix* - для 3 группы. 
> 
> Так как для 3 группы ты использовал не один большой скрипт, а много маленьких, то у меня для тебя плохая новость.
> Для создания вьюхи тебе нужно будет собрать все свои скрипты в одну большую портянку.
> В смысле скрипт.
> 
> Весь код для создания 3 вьюх должен быть написан в файле *src/task_9.sql*.
> 
> P.S. Разберись, куда в дереве БД в **DBeaver** сохранились вьюхи. Не забудь обновить дерево после создания вьюх.
